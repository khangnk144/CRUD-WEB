# 06. Next.js 20/80

Mục tiêu: hiểu phần Next.js cần cho CRUD app.

## Next.js là gì?

Next.js là framework dựa trên React. Nó thêm routing, server rendering, API route và cấu trúc project thực tế hơn.

## App Router

Trong Next.js App Router:

```txt
app/
  layout.tsx
  page.tsx
  jobs/
    page.tsx
```

Ý nghĩa:

- `app/page.tsx`: trang `/`.
- `app/jobs/page.tsx`: trang `/jobs`.
- `app/layout.tsx`: layout chung.

## Client component

Nếu component dùng `useState`, `useEffect`, event handler, cần `'use client'`.

```tsx
'use client';

import {useState} from 'react';

export function JobSearch() {
  const [keyword, setKeyword] = useState('');

  return <input value={keyword} onChange={(event) => setKeyword(event.target.value)} />;
}
```

## API route

```ts
// GET xử lý request lấy dữ liệu.
export async function GET() {
  return Response.json({
    data: [],
  });
}
```

## Fetch API

```ts
// fetch gọi API từ frontend.
// await chờ API trả kết quả trước khi chạy dòng tiếp theo.
const response = await fetch('/api/jobs');
const responseBody = await response.json();
```

## Cần nắm chắc

- File path tạo route.
- Component nào dùng state/event thì là client component.
- API route chạy phía server.
- Không đưa secret vào client component.
- Tách logic gọi API vào helper khi code bắt đầu dài.

## Next.js khác React thường ở đâu?

React chủ yếu là thư viện xây UI. Next.js là framework xây app hoàn chỉnh hơn.

Next.js thêm:

- File-based routing.
- Server component.
- Client component.
- API routes.
- Build/deploy convention.
- Metadata, layout, loading, error page.

Với project CRUD-WEB, ta dùng Next.js vì muốn học luồng gần thực tế:

```txt
Page UI
  -> gọi API route
  -> API route gọi database
  -> trả JSON về UI
```

## App Router chi tiết

Ví dụ:

```txt
app/
  layout.tsx
  page.tsx
  jobs/
    page.tsx
  api/
    jobs/
      route.ts
```

Route tạo ra:

- `app/page.tsx` -> `/`
- `app/jobs/page.tsx` -> `/jobs`
- `app/api/jobs/route.ts` -> `/api/jobs`

`layout.tsx` bọc các page bên trong. Thường dùng để đặt HTML chung, font, global CSS.

## Server component và client component

Mặc định component trong App Router là server component.

Server component:

- Chạy trên server.
- Có thể đọc database trực tiếp.
- Không dùng `useState`.
- Không dùng `onClick`.
- Không dùng browser API như `localStorage`.

Client component:

- Chạy trên browser.
- Có thể dùng `useState`, `useEffect`.
- Có thể xử lý click, submit form.
- Cần dòng `'use client'` ở đầu file.

Ví dụ client component:

```tsx
'use client';

import {useState} from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button
      onClick={function () {
        setCount(count + 1);
      }}
    >
      Count: {count}
    </button>
  );
}
```

## Khi nào dùng client component trong CRUD-WEB?

Dùng client component cho:

- Form thêm/sửa job.
- Search input.
- Filter dropdown.
- Button edit/delete.
- UI cần state loading/error.

Dùng server/API code cho:

- Đọc database.
- Ghi database.
- Dùng secret từ `.env`.
- Validate dữ liệu backend.

## API route chi tiết

File:

```txt
app/api/jobs/route.ts
```

Ví dụ:

```ts
// GET xử lý request GET /api/jobs.
// Function này chạy trên server, không chạy trong browser.
export async function GET() {
  const jobs = [];

  return Response.json({
    data: jobs,
  });
}
```

POST:

```ts
export async function POST(request: Request) {
  // request.json() đọc body JSON từ frontend gửi lên.
  const body = await request.json();

  return Response.json(
    {
      data: body,
    },
    {
      status: 201,
    },
  );
}
```

Giải thích:

- `Request` chứa thông tin request.
- `request.json()` parse JSON body.
- `Response.json()` trả JSON response.
- `status: 201` nghĩa là tạo mới thành công.

## Dynamic route cho job id

Để có `/api/jobs/:id`, tạo:

```txt
app/api/jobs/[jobId]/route.ts
```

Ví dụ:

```ts
type RouteParams = {
  params: {
    jobId: string;
  };
};

export async function DELETE(request: Request, {params}: RouteParams) {
  const jobId = params.jobId;

  return Response.json({
    data: {
      deletedJobId: jobId,
    },
  });
}
```

## Gọi API từ frontend

```tsx
async function loadJobs() {
  setIsLoading(true);
  setErrorMessage('');

  try {
    const response = await fetch('/api/jobs');
    const responseBody = await response.json();

    setJobs(responseBody.data);
  } catch (error) {
    setErrorMessage('Cannot load jobs');
  } finally {
    setIsLoading(false);
  }
}
```

Giải thích:

- `try`: chạy code có thể lỗi.
- `catch`: xử lý khi có lỗi.
- `finally`: luôn chạy dù thành công hay thất bại.
- `setIsLoading(false)` đặt trong `finally` để loading luôn tắt.

## Loading và error page trong Next.js

Next.js hỗ trợ file đặc biệt:

```txt
app/jobs/loading.tsx
app/jobs/error.tsx
```

Nhưng với phase đầu, có thể xử lý loading/error trong client component cho dễ hiểu.

## Lỗi Next.js thường gặp

1. Dùng `useState` nhưng quên `'use client'`.

2. Dùng `localStorage` trong server component.

3. Đưa secret vào client code.

4. Nhầm `app/api/jobs/page.tsx` với `app/api/jobs/route.ts`.

5. API route không return response.

## Bài tập nhỏ

1. Tạo page `/jobs`.
2. Tạo API `GET /api/jobs`.
3. Frontend gọi API và hiển thị jobs.
4. Thêm loading state.
5. Thêm error state.
6. Tạo API `POST /api/jobs`.
7. Submit form gọi POST.
